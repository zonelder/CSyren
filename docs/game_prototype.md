# Movement / shooter prototype (Titanfall-style)

Prototype of pilot movement with a hitscan rifle, a physical grenade launcher,
a test range and target bots. Runs in the editor play mode: open
`assets/movement_polygon.scene` (the project start scene), press **Play**, click
the **Game** view to capture the mouse.

## Controls

| Key | Action |
| --- | --- |
| Mouse | look (click Game view to capture, `Esc` releases) |
| `W A S D` | move (walk 5 m/s) |
| `Shift` | sprint (8 m/s; `PilotConfig.ground.alwaysSprint` makes it automatic) |
| `Space` | jump; in the air: wall kick if touching/facing a wall, otherwise double jump |
| `Ctrl` / `C` | crouch; while sprinting: slide; hold in the air: slide on landing |
| `LMB` | fire |
| `R` | reload |
| `Q`, `1`, `2` | switch weapon |
| `F5` | respawn (also automatic when falling out of the level) |

Movement rules (see `game/pilot_movement_system.h`):

* **Ground**: Source-style friction + acceleration. Holding jump when landing
  (or a buffered press) jumps again without friction, so bunny hopping keeps
  momentum.
* **Air**: gravity, Quake air-strafing (gains speed with strafe + mouse), plus
  direct air control that never increases speed above what you already had.
* **Double jump**: once per airtime; re-aims momentum toward the input
  direction (`doubleJumpRedirect`). Refreshed by landing or touching a wall.
* **Slide**: crouch above `slide.minSpeed`; initial boost, low friction, slope
  gravity, limited steering. Jumping out of a slide keeps the speed (slide hop).
* **Wallrun**: airborne and touching a wall (any side; the physics contact is
  the trigger, side casts are the fallback), or a wall within `wall.checkDistance`;
  entering at an angle redirects the speed along the wall. Gravity ramps from `gravityScale` to full over `gravityRamp`
  seconds, runs end after `maxTime`, when looking/pushing away, or when the wall
  ends. Jump = wall jump (away + up + forward). The same wall *plane* cannot be
  re-run until the ground or another wall is touched; touching any wall
  refreshes the double jump. Camera rolls away from the wall.
* **Mantle**: moving forward into a ledge between `mantle.minHeight` and
  `maxHeight` pulls the pilot up onto it.

All numbers live in the `PilotConfig` component of the `pilot` entity and can
be tuned live in the inspector (the runtime scene is a copy; stop and edit the
editor scene to keep the values).

## Engine additions

### Physics (`lib/physics`)

* `PhysicsSystem` steps with a fixed time step (`core::Time::fixedDeltaTime`,
  set to 1/120 s in `Application::run`) using an accumulator (max 8 steps per
  frame) and writes **interpolated** poses to `Transform`, so motion is smooth
  at any frame rate. A `Transform` equal to the pose written last frame is not
  treated as a teleport; editing it (or moving kinematic bodies) still teleports.
* Collision layers are named and project-defined (`physics::PhysicsLayers`,
  see `docs/physics_layers.md`); the game registers `Default`, `Player`,
  `Projectile`, `Trigger` in `game/game_physics.h`. `RigidBody::layer` /
  `CharacterController::layer` hold the name.
* `CharacterController` component: a Jolt `CharacterVirtual` capsule driven by
  a desired velocity. Outputs `grounded`, `groundNormal`, `wallContact`,
  `currentHeight` (crouch resizing) and the post-collision `velocity`.
* Queries on `PhysicsEngine`: `raycast`, `sphereCast`, `overlapSphere` with a
  layer mask and an ignored entity; `addImpulse`; `contacts()` with the contacts
  that started during the last frame (used by projectiles).
* `RigidBody::continuousCollision` enables `LinearCast` motion quality (projectiles).

### Assets

* glTF import, lit shaders, `AnimationClip` resources and `Animator` playback:
  see `docs/asset_pipeline.md`. Weapon view models come from
  `assets/models/*.glb` (generated by `tools/make_weapon_models.py`).

### Rendering

* Deferred PBR pipeline with clustered point lights, a forward pass for
  transparent materials and HDR tonemapping: see `docs/rendering.md`.
  Lights are `DirectionalLight` / `PointLight` components, scene settings live
  in `LightingSettings` (ambient, exposure, debug views).

### Editor

* **File → Import model…** instantiates a `.glb`/`.gltf` as an entity tree (undoable).
* **Edit → Save object as prefab…** writes the selected object and its children
  to a `.prefab` file; **File → Instantiate prefab…** places a copy (undoable).
  `PrefabRef` fields show the path and whether the file exists.
* `editor::EditorOverlays` service: named ImGui callbacks drawn by `EditorSystem`
  after its windows. The game HUD (crosshair, speed, state, ammo) uses it.

## Game layer (`game/`)

| File | Purpose |
| --- | --- |
| `game_components.*` | `PlayerTag`, `PilotConfig` (+ nested tuning structs), `PilotState`, `WeaponInventory`/`WeaponDef`, `Projectile`, `Health`, `Bot`, `Lifetime` |
| `player_input*.h` | `PlayerInput` service + `PlayerInputSystem` (mouse capture, edge-triggered keys) |
| `pilot_movement_system.h` | movement state machine, writes `CharacterController::velocity` and the pilot yaw |
| `camera_rig_system.h` | camera child: pitch, wallrun roll, crouch eye height, landing dip, recoil, FOV kick |
| `view_model_system.h` | first-person weapon models: slot visibility, sway/bob/recoil/switch/reload motion, muzzle position |
| `weapon_system.h` | fire/reload/switch, hitscan raycast with impact markers, projectile spawning |
| `projectile_system.h` | explosion on contact/timeout: damage falloff, impulses, marker |
| `bot_system.h` | target bots (idle/patrol/chase), hit flash, death/respawn; `LifetimeSystem` |
| `game_hud.h` | `GameHud` snapshot service + HUD overlay |
| `game_materials.h` | flat-colored procedural materials (`__game_mat_*`) + `GameSetupSystem` |

System order in `assets/app.systems`: `PlayerInputSystem` (input) →
`PilotMovementSystem` → `PhysicsSystem` → `AnimationSystem` → `CameraRigSystem` → `ViewModelSystem` → `WeaponSystem` →
`ProjectileSystem` → `BotSystem` → `LifetimeSystem` → `GameHudSystem` → render.
Ordering is expressed with `before`/`after` in each system's `describe()`.

## Test range

`tools/gen_polygon_scene.py` writes `assets/movement_polygon.scene`. Areas
(player spawns at the south end, looking north):

* **Corridor** straight ahead: alternating wall segments for wallrun → jump →
  wallrun chains, finishing on a 3.5 m platform.
* **West**: an 18° slide ramp with a stair of 1.0 / 1.9 / 2.8 m ledges to
  mantle, bumps on the landing for slide hops, and a 40 m wall along the edge.
* **East**: jump towers (1.2 / 2.2 / 3.3 / 4.6 m) with a tall wall beside the
  last one, and two platforms 7 m apart for double-jump gaps.
* **North**: shooting arena with cover, idle / patrolling / chasing bots. Two
  bots stand next to the spawn for quick weapon tests.
* **Lighting**: a sun plus ~20 colored lamps (emissive blocks with point
  lights) along the corridor, towers, long wall and arena; metal spheres and
  glass panels next to the spawn show specular / transparent materials.

Edit the script and re-run it to change the layout; keep the scene file in sync.

## Feel checklist

1. Bhop chain on flat ground: speed does not drop between hops.
2. Slide → jump → land crouched → slide: speed carries over.
3. Corridor: right wall → jump → left wall → jump → right wall → platform.
4. Wall jump from a wallrun lands on a platform 3+ m up.
5. Double jump redirect: jump forward, press back + Space, land behind the start.
6. Mantle the 1.9 m and 2.8 m (needs a jump) stairs.
7. Rifle hits flash the bot, launcher explosions knock the dynamic cubes.
